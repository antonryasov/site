# Как публиковать посты в канал автоматически

Посты пишутся в очередь, очередь публикуется скриптом. Ниже — что нужно сделать один раз (2 минуты) и как это работает дальше.

**Что уже готово в очереди:** 55 постов. Первые пять (id `01`–`05`) — без даты, уходят сразу при первом запуске. Дальше серия из 50 постов (id `06`–`55`), по одному в день, **09.11.2026 → 28.12.2026, каждый день в 20:00 по Москве**.

---

## Шаг 1. Отдельный бот для публикации

**Не используйте того же бота, что принимает заявки с сайта** (`@ryasov_leads_bot`). Его токен лежит в исходниках сайта, то есть фактически опубликован. Если дать этому боту право публиковать в канале, любой, кто откроет исходник страницы, сможет писать в канал от вашего имени.

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Имя, например: `Рясов · публикатор`. Username: `ryasov_publisher_bot` (любой свободный).
3. BotFather выдаст токен вида `8123456789:AAH...` — это ключ к каналу. Никому его не показывайте и не вставляйте в сайт.

## Шаг 2. Подключить бота к каналу

1. Канал «Ну такое от Антона» → **Управление** → **Администраторы** → **Добавить администратора**.
2. Найдите своего бота по username → добавьте.
3. Оставьте включённым только право **«Публикация сообщений»** (и, если хотите, «Удаление сообщений»). Остальные права не нужны.

## Шаг 3. Положить токен туда, где ему место

Токен не должен попасть ни в сайт, ни в git. Два рабочих места:

**Локально** — файл `.env` рядом со скриптом:

```
TG_BOT_TOKEN=8123456789:AAH...
```

Файл `.env` уже в `.gitignore`. Проверка:

```bash
cd telegram
python3 tg-publish.py --check
```

Ожидаемый ответ:

```
Бот: @ryasov_publisher_bot («Рясов · публикатор», id ...)
Канал: Anton_77 (nu_takoe_ot_antona, id -1001050749044)
Статус бота в канале: administrator, право публикации: есть

Всё готово: можно публиковать — python3 tg-publish.py --next
```

**На GitHub** — Settings → Secrets and variables → Actions → New repository secret, имя `TG_BOT_TOKEN`. Тогда публикует workflow по расписанию, токен в файлах не лежит.

## Как это работает дальше

| Что | Команда |
|---|---|
| Что в очереди и что уже вышло | `python3 tg-publish.py --list` |
| Проверить бота и права | `python3 tg-publish.py --check` |
| Посмотреть, что уйдёт сейчас, без отправки | `python3 tg-publish.py --next --dry-run` |
| Опубликовать всё, что уже пора | `python3 tg-publish.py --next` |
| Опубликовать конкретный пост | `python3 tg-publish.py --id 21` |

Очередь — файл `telegram/очередь.json`. После публикации у поста меняется `status` на `опубликован`, сохраняются `message_id` и `published_at`, скрипт печатает ссылку вида `https://t.me/nu_takoe_ot_antona/290`.

**Правило `--next`.** Команда публикует все посты со статусом `готов`, у которых `publish_after` пустой или уже наступил по Москве, — но не больше пяти за один запуск (ограничение `--max`, по умолчанию 5). Поэтому:

- первый запуск публикует сразу пять постов (у них нет даты);
- дальше каждый день «созревает» ровно один пост серии — и уходит ровно один;
- если день пропущен, следующий запуск догонит: пара постов выйдет вместе, но ничего не потеряется.

**Расписание.** В архиве сайта есть `.github/workflows/tg-publish.yml`: каждый день в **20:00 по Москве** он берёт из очереди то, что уже пора, публикует, обновляет живую ленту на странице `#/telegram` и коммитит изменения. GitHub может задержать запуск по расписанию на 5–20 минут — на смысл это не влияет.

**Даты.** У каждой поста серии в поле `publish_after` стоит `ГГГГ-ММ-ДДT20:00+03:00`. Раньше этой даты пост не уйдёт. Все даты сразу — в `telegram/50-постов-расписание.md`. Чтобы сдвинуть старт, поменяйте `SERIES_START` в `parts/tg_posts.py` и запустите `python3 parts/tg_posts.py`.

## Что делать, если что-то не так

| Ответ API | Что значит | Что сделать |
|---|---|---|
| `chat not found` | Бот не в канале | Добавить бота администратором канала |
| `not enough rights to send text messages` | Бот в канале, но без права публикации | Включить право «Публикация сообщений» |
| `Unauthorized` | Токен неверный или отозван | BotFather → `/mybots` → API Token, обновить `.env` |
| `Too Many Requests: retry after N` | Слишком много публикаций подряд | Подождать N секунд, не гонять `--next` в цикле |

Проверить всё сразу: `python3 tg-publish.py --check`.

## Безопасность коротко

- Токен — только в `.env` или в Secrets. Никогда в `index.html`, `очередь.json` и README.
- Если токен засветился: BotFather → `/revoke` → новый токен → заменить в `.env` и в Secrets. Старый перестаёт работать сразу.
- Права бота — минимальные: публикация сообщений. Не давайте «Изменение информации о канале» или «Добавление участников».
- `.env` не попадает в архивы сайта и в git: он в `.gitignore`.

## Тексты постов

- `telegram/очередь.json` — очередь для публикации (то, что реально уходит в канал): 55 постов с текстами и датами.
- `telegram/5-постов.md` — первые пять текстов для копирования руками.
- `telegram/50-постов-расписание.md` — таблица серии: номер, дата, день недели, тема.
- `telegram/50-постов-тексты.md` — все 50 текстов серии одним файлом, чтобы читать и править.
- Исходники — `parts/tg_sel.py` (первые пять) и `parts/tg_posts.py` (серия 50). Правите текст там, пересобираете `python3 parts/tg_posts.py` — очередь и расписание обновляются. Статусы, `message_id` и даты уже опубликованных постов при этом сохраняются.

### Если тексты правите в очереди напрямую

Можно и так: `telegram/очередь.json` — обычный JSON, поле `text`. Одна оговорка — при следующей пересборке (`python3 parts/tg_posts.py`) тексты перезапишутся из `parts/tg_posts.py`. Поэтому правки лучше вносить в исходник.
