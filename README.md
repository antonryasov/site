# Сайт Антона Рясова

Статический сайт-портфолио: стратегия и маркетинг в гостеприимстве.

## Состав

| Файл | Зачем |
|---|---|
| `index.html` | Весь сайт одним файлом: стили, шрифты, изображения внутри |
| `unit-economics/` | Калькулятор юнит-экономики — отдельная страница, один файл `index.html` |
| `funnel/` | Диагностика воронки — отдельная страница, один файл `index.html` |
| `archetypes/` | Отдельная страница «Симулятор архетипов бренда» (один файл `index.html`, ссылка — на «Материалах» и в подвале) |
| `forecast/` | Прогноз спроса — 12 месяцев истории, четыре метода, MAPE, страховой запас |
| `abc-xyz/` | ABC/XYZ-анализ ассортимента — матрица 3 × 3 с решениями |
| `pricing/` | Симулятор цены — эластичность, кривая прибыли, точка максимума |
| `bonuses/` | Библиотека из 10 PDF: 01–03 скачиваются сразу (главная и «Материалы»), 04–10 открываются после заявки на странице «Спасибо» |
| `tg-feed.py` | Утилита обновления живой ленты Telegram на странице «Телеграм» (без зависимостей) |
| `tg-publish.py` | Публикация постов из очереди `telegram/очередь.json` в канал через Bot API |
| `telegram/очередь.json` | Очередь постов: что уже вышло, что готово к публикации |
| `.github/workflows/tg-feed.yml` | Автообновление ленты раз в сутки через GitHub Actions (по желанию) |
| `.github/workflows/tg-publish.yml` | Публикация очередного поста раз в сутки (нужен секрет `TG_BOT_TOKEN`) |
| `.nojekyll` | Отключает обработку Jekyll на GitHub Pages |

## Публикация (GitHub Pages)

1. Загрузите файлы в корень репозитория (`index.html`, папку `bonuses`, `.nojekyll`).
2. Settings → Pages → Deploy from a branch → `main` → `/ (root)` → Save.
3. Через 2–5 минут сайт откроется по адресу `https://username.github.io/repo/`.

Подробная инструкция — в файле `Как-запустить-сайт-на-GitHub.md` (не входит в архив для загрузки).

## Формы

Заявки приходят в Telegram, в бота **@ryasov_leads_bot**. Нужно один раз нажать у него **Start** — после этого все шесть форм сайта доставляют сообщения мгновенно (имя, почта, задача, страница, источник).

Если Telegram недоступен, гость не теряет заявку: форма предлагает отправить письмо, написать в Telegram или скопировать текст заявки одним нажатием.

Токен бота находится в `index.html` в блоке `LEAD_CONFIG`. При спаме перевыпустите его через `/revoke` в @BotFather и замените строку `telegram.token`.

## Лента Telegram на странице «Телеграм»

Страница `#/telegram` показывает последние посты канала «Ну такое от Антона» и подборку из пяти постов. Лента **не** использует виджеты и внешние скрипты: посты забираются при публикации сайта и лежат в `index.html` готовыми карточками.

Обновить ленту вручную (после того как вышли новые посты):

```bash
python3 tg-feed.py --patch index.html
```

Проверить, что подтягивается, без изменения файла: `python3 tg-feed.py --print`.

**Автоматически.** Если в репозитории есть файл `.github/workflows/tg-feed.yml`, лента обновляется раз в сутки сама: Actions → «Обновить ленту Telegram». Коммит появляется только когда в канале действительно есть новые посты. Если автоматизация не нужна — просто удалите папку `.github`.

**Что попадает в ленту.** Только посты с текстом длиннее 140 символов: мемы, картинки без подписи и короткие репосты остаются в Telegram. Порог меняется одной строкой `MIN_LEN` в начале `tg-feed.py`.

## Публикация постов в канал

Посты лежат в очереди `telegram/очередь.json`. Публикует их бот-публикатор — **не** тот бот, что принимает заявки с сайта: у того токен лежит в исходнике страницы, давать ему права в канале нельзя.

Один раз:

1. [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
2. Канал → Управление → Администраторы → добавить бота → право **«Публикация сообщений»**.
3. Токен: локально — в файл `.env` (`TG_BOT_TOKEN=...`, файл в `.gitignore`); на GitHub — в Secrets под именем `TG_BOT_TOKEN`.

Публикация:

```bash
python3 tg-publish.py --check     # бот, канал и права
python3 tg-publish.py --list      # что в очереди
python3 tg-publish.py --next      # опубликовать всё, что уже пора
```

В очереди 55 постов: пять стартовых (уходят при первом запуске сразу) и серия из 50 — по одному в день, **09.11.2026 → 28.12.2026, в 20:00 по Москве**. Даты лежат в поле `publish_after`, расписание таблицей — `telegram/50-постов-расписание.md`.

По расписанию это делает `.github/workflows/tg-publish.yml`: раз в сутки в **20:00 по Москве** публикует то, что уже пора, обновляет ленту на сайте и коммитит результат. Пока секрет не задан, workflow просто пропускает запуск.

Файлы:

| Файл | Что внутри |
|---|---|
| `telegram/очередь.json` | 55 постов с текстами и датами (`publish_after`) |
| `telegram/50-постов-расписание.md` | Таблица серии: номер, дата, день недели, тема |
| `telegram/50-постов-тексты.md` | Все 50 текстов одним файлом — читать и править |
